## Automated acceptance run

`bash scripts/smoke-mac.sh` proves the primary workflow inside the real desktop app, with no GUI automation.
It builds a debug app once (`pnpm tauri build --debug --no-bundle` → `src-tauri/target/debug/opal`, frontend
embedded; `--no-build` reuses it) and launches it twice with `OPAL_HOME=/private/tmp/opal-smoke-<pid>/home`
(isolated settings, sidecar config/data, sandboxes, versions; `~/Library/Application Support/Opal` is never touched)
and `OPAL_SMOKE=<config.json>`. With `OPAL_SMOKE` set, `src/main.tsx` starts the harness in `src/lib/smoke`, which
drives the real `runtime` stores against the bundled sidecar, writes `<OPAL_HOME>/logs/smoke-<name>.json`
(`cmd_smoke_report`, `src-tauri/src/smoke.rs`), stops the sidecar and exits (code 1 when `ok` is false).
Without the variable the harness is inert.

| Phase  | Step                 | Checks (criteria)                                                                                                                                                                                                                                  |
| ------ | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| create | `server`             | sidecar ready (version + URL, no password), Opal's agents applied to `opencode.json` (1)                                                                                                                                                           |
| create | `provider`           | `importOpenCodeConfig()` imports ≥1 provider from `~/.config/opencode/opencode.json` (key → credential store, never printed); the requested model is listed by the catalog; `defaultModel` / `defaultMode: artifact` saved to settings.json (2, 3) |
| create | `session`            | `createSession({surface:"chat", mode:"artifact"})`; its directory is `<OPAL_HOME>/conversations/<sessionID>` and exists; UI navigated to it (4)                                                                                                    |
| create | `turn1`              | prompt 1 sent, activity busy → idle within the timeout (15 min); ≥1 assistant message with text; an artifact with an `.html` file; tool names recorded (5, 6)                                                                                      |
| create | `preview1`           | `cmd_smoke_artifact_file` (same resolver as the `artifact://` handler) → 200 `text/html`; the pane opens by itself; the iframe reaches `data-preview-status="rendered"` with `src` on `artifact://localhost/` (7, 8)                               |
| create | `turn2`              | prompt 2 updates the **same** artifact id (`time.updated` advances); the iframe `src` nonce changes and the status re-cycles to rendered; ≥2 version snapshots (9, 10, 11)                                                                         |
| reopen | `server`, `settings` | relaunch on the same data: providers + default model persisted and still listed (12)                                                                                                                                                               |
| reopen | `listed`, `messages` | the conversation is listed for the chat surface; transcript loads with ≥2 user messages (13)                                                                                                                                                       |
| reopen | `artifact`           | the artifact is listed and the pane opens by default and renders from `artifact://localhost/<id>/…` (13)                                                                                                                                           |

Each step records `ms`, a `detail` object and, on failure, `error`; the run stops at the first failure and the
report always gets written (`ok:false`, `failedStep`). Permission prompts raised during a turn are approved once
and listed in the step detail (`permissionsApproved`). Options: `--keep` (keep reports, app logs and data),
`--model provider/id` (default: the CLI config's `model`), `--timeout-ms`.
